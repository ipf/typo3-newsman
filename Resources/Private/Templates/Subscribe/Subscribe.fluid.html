The stylesheet of the form is loaded by the template: TYPO3 v14 has no configureExtension() any more, and the form is only ever rendered inside a page, where the asset is collected with the page. The message is rendered here rather than with f:flashMessages: the controller hands over a label key, and LanguageService is no longer available as a DI service since TYPO3 v13. newsmanMessage holds editor text (a FlexForm success message wins), so it is not passed through f:translate; newsmanMessageKey is a label that is. The texts of the field and of the button are plain texts of the FlexForm, not labels: the site of this package brings its own wording, and an inline f:if with a f:translate inside would have to be repeated in every attribute. They are written into the view, not escaped again by an f:variable, because a ViewHelper inside the inline content of an f:variable produces no output.

{newsmanMessage}

The name is what puts the fields into the plugin namespace: without it the input is posted as plain "email" and the controller never sees it, because Extbase only reads arguments of tx_newsman_subscribe.
